출발: AI 채팅 메뉴 추천 앱

처음 버전
배경
AI가 아이디어부터 구조, 코드까지 만든 웹앱에서 출발했어요. Ollama(llama3.1)에게 "점심 추천해줘"라고 채팅으로 묻는 방식이었어요.

동작은 했지만 답변 하나에 약 47초가 걸렸어요. 더 작은 모델(llama3.2:3b)은 한국어가 깨졌어요.

문제 다시 찾기

기획 전환점
질문
"이런 건 이미 많이 있을 텐데, 똑같다면 만들 필요가 없지 않나?" 그리고 "그건 AI가 짠 거잖아."
판단
채팅 추천은 ChatGPT가 이미 더 빠르고 잘해요. 이 버전에는 "왜 만드는지"가 없었어요. 그래서 문제부터 다시 찾기로 했어요.
찾은 문제
원하는 건 있는데, 그게 뭔지 말로 꺼내지 못한다.
ChatGPT는 원하는 걸 말로 설명해야 해요. 바로 그걸 못 하는 사람이 우리 사용자예요. 이게 차별점이에요.
배운 점
기능이 아니라 문제에서 출발하기. 이미 있는 것과 무엇이 다른지 묻기

사용자 심리와 설계 원칙

기획
논의
  • 사람은 조사받는 것을 싫어함 ("왜 물어봐? 어디에 쓰려고?")
  • 그러니 결과를 먼저 보여 주고, 클릭으로 정보를 활용해서 점점 원하는 것을 찾게 하자
  • 그래도 출발점은 필요함 → 기본 질문(독립변수): 기분, 인원수, 재료(선택)
  • 식사 시간은 자동이 아니라 클릭으로 (점심에 저녁 메뉴를 고를 수도 있음)
  • 날씨는 위치 정보가 필요해서 나중 버전으로
설계 원칙
심리원칙
회상 vs 재인 (보고 알아보기가 쉬움)묻지 말고 메뉴를 먼저 보여 준다
선택 과부하한 번에 5개만
조사 거부감개인정보 받지 않기, 버튼 클릭 위주, 안심 문구
콜드 스타트 문제기분, 인원, 재료, 식사 시간을 출발점으로
배운 점
독립변수와 종속변수, 콜드 스타트, 사용자 심리를 설계로 옮기기

test 2.1: 마지막 한 걸음은 AI가

test 2.1
문제 제기
계획과 어긋남 "결과를 보면 결국 사용자가 선택한 것이 나오잖아. 처음 계획에 맞지 않는다." 앞의 피드백을 "분석을 아예 쓰지 말자"로 너무 넓게 해석했던 것이 원인이었어요.
정리
분석을 말로 보여 주기(❌)와 분석으로 메뉴를 찾아 주기(✅)를 나눠요.
아이디어
고른 두 메뉴 중 초기 입력을 바탕으로 AI가 하나 추천, 다른 음식을 보고 싶으면 "원 모어 띵크" 버튼
구현
  • 🤖 오늘은 이거예요!: 고르는 건 점수 계산(즉시), AI는 한 줄 코멘트만 작성
  • 🤔 원 모어 띵크: 처음엔 가까운 메뉴, 점점 다른 종류. 결과는 아래로 쌓임
  • AI 안전장치: 규칙(40자, 사람 판단 금지), 출력 검사, 40초 타임아웃 → 틀 문장, 서버 시작 시 워밍업
  • 당기는 재료 → 필수 재료 (가산점 → 걸러내기)
결과
감자탕 → 뼈해장국을 고르면 "오늘은 이거예요! 뼈해장국"과 💬 "피곤한 밤에 부드럽고 따뜻한 국물이 딱 좋다."(9초) 원 모어 띵크는 콩나물국밥 → 순대국밥 → 라면.
배운 점
AI와 규칙의 역할 나누기, 대체 경로(fallback), 출력 검증, 타임아웃, 워밍업, 비동기 화면 채우기

사용 테스트와 다음 구상

진행 중
방식
직접 써 보면서 고칠 것을 말하면, 바로 고치지 않고 목록에 모아 두었다가 한 번에 고치기로 했어요.
나온 의견
  • [이전]이 시작 화면으로 가면 안 됨 → 1라운드에서는 이전 버튼을 없앰
  • 한식, 중식, 일식, 분식, 양식 분류가 좋다 → 종류를 늘려 데이터로 넣고 다른 방향 보기에 활용
  • 이것을 우리 DB로 만들자 → 정보가 쌓이면 자산
  • 사용자 선택을 DB화하면 개인 성향을 알 수 있지 않을까 → 개인정보 문제를 검토 → 선택 로그인 (안 해도 되고, 하면 그간의 데이터를 볼 수 있음)
  • 로그인하면 AI가 개인 성향을 분석해서 추천하고, 그간 선택한 메뉴를 보는 새 버튼
검토한 것
집단 성향 vs 개인 성향, 개인정보보호법(동의, 최소 수집, 암호화, 삭제), 필수 로그인 vs 선택 로그인, "취향 감옥" 문제

문제

  • 필수 재료 → 키워드: 이름·종류·특징·재료를 모두 찾고, 비슷한 말(매콤·얼큰 → 매움)도 이해
  • 여러 단어: 모두 맞음 → 하나라도 → 전체 + 안내 (결과가 0개가 되지 않게)
  • 안내 문구는 누른 버튼 바로 아래
  • "수정만" 요청으로 바로 고친 것: 번호 배지 ①~④, 휴대폰 폭, 카드마다 카카오맵, [메뉴 보기] 위치

새 파일 keywords.py(사전·불용어·AND/OR/전체), API 필드 keyword, 안내 위치 이동(click capture + after())

관련 메뉴 그래프(무엇을) + 태그 점수표(어떤 순서로) + 개인 취향

키워드    = 비슷한 말 사전으로 이해 → 모두 맞는 메뉴만 → 없으면 하나라도 → 없으면 전체 + 안내   (test 3.2)
메뉴 점수 = Σ(메뉴 태그의 점수) + 식사 시간 맞음 +2.0 / 안 맞음 -5.0 + 키워드 조건 1개당 +2.0 + 무작위 0~0.8
태그 점수 = 기분 + 인원 + 계절·요일 + 안주(야식)·간편식(혼자)
          + 고른 메뉴 태그 +1.5 / 넘긴 메뉴 태그 -0.5          (다른 방향 보기에서는 ×0.5)
          + 개인 취향: 최근 결정 메뉴의 태그 비율 × 2.0         (로그인 · 기록 3개 이상, 다른 방향 ×0.5)
룰렛      = 위 점수로 다양한 종류 10칸 → 당첨은 칸 중 무작위 (바로 전 당첨 제외)
