# 오늘 뭐 먹지? (menu-recommender) — `test 1.0`

> **"뭘 먹고 싶은지 모르겠다. 그런데 먹고 싶은 게 없는 건 아니다."**
> 이 사람을 위한 앱이에요. 묻지 않고, 메뉴를 먼저 보여 주고, 클릭을 보며 마음을 읽어서 진짜 원하는 메뉴로 좁혀 가요.

## 사용 방법 (test 1.0)

1. **시작 화면**: 식사 시간(현재 시각으로 자동 선택), 기분, 인원수, 재료를 골라요. 식사 시간 말고는 모두 선택 사항이에요.
2. **라운드 화면**: 메뉴 5개 중 **끌리는 것만 클릭**하고 [다음]을 눌러요. 클릭하지 않은 메뉴는 빠지고, 비슷한 성향의 새 메뉴가 채워져요. 최대 4라운드까지 진행해요.
   - **[◀ 이전]**: 앞 라운드로 돌아가요. 그때의 메뉴와 ✓ 선택 상태가 그대로 다시 나와요. 1라운드에서는 시작 화면으로 돌아가요.
3. **결과 화면**: **내가 고른 메뉴**가 모두 나와요. 여러 라운드 동안 오래 남아 있던 메뉴일수록 위에 있어요(👑).
   - 성향 분석 결과는 화면에 보여 주지 않아요. 분석은 뒤에서 다음 메뉴를 고르는 데만 써요.

## 실행 방법

```
docker compose up -d --build
```

브라우저에서 **http://localhost:5500** 에 접속하면 돼요.

> test 1.0 화면은 AI(Ollama)를 사용하지 않아요. 태그 점수 계산만으로 즉시 동작하기 때문에 **모델을 받지 않아도 실행돼요.**
> 아래 모델 다운로드는 이전 버전의 AI 채팅(`/api/chat`)이나 나중에 추가할 AI 기능에만 필요해요.

컨테이너 안의 Ollama에 모델을 받아 두는 방법이에요. 한 번만 하면 돼요.

```
docker exec -it menu-ollama ollama pull llama3.1
```

> 더 작은 모델(llama3.2:3b)도 시도해봤지만 한국어 응답 품질이 많이 떨어져(단어 깨짐, 외국어 혼입) llama3.1(8B)을 기본값으로 사용합니다. GPU가 없는 환경이라 응답에 첫 요청은 수 분, 이후에는 모델이 메모리에 로드된 상태라 20초 내외가 걸립니다.

### API 주소 (test 1.0)

| 주소 | 하는 일 |
|---|---|
| `POST /api/round` | 입력값과 클릭 기록을 받아서 다음 라운드 메뉴 5개를 돌려줌 |
| `GET /health` | 서버 상태와 버전 확인 |
| `POST /api/chat` | (이전 버전) AI 채팅. 지금 화면에서는 사용하지 않음 |

http://localhost:8001/docs 에 들어가면 API 문서를 보면서 직접 테스트해 볼 수 있어요.

## 컨테이너 구성

- `menu-ollama` : Ollama 서버 (포트 11434), 모델은 `ollama_data` 볼륨에 저장되어 재시작해도 유지됨
- `menu-backend` : FastAPI 서버 (호스트 포트 8001 → 컨테이너 8000), 컨테이너 내부에서 `http://ollama:11434`로 Ollama 호출. 8000번은 `investment_backend` 컨테이너가 이미 사용 중이라 8001로 매핑했습니다.
- `menu-frontend` : 정적 파일 서버 (포트 5500)

`docker-compose.yml`의 `backend` 서비스 `OLLAMA_MODEL` 환경변수를 원하는 Ollama 모델명으로 바꾸고,
`docker exec -it menu-ollama ollama pull <모델명>`으로 받은 뒤 재시작하면 됩니다.

- 그래서 **문제부터 다시 찾기**로 했다. 지금 버전은 웹 서비스 구조를 공부하는 연습용 교재로 남겨 둔다.

### ✅ 해결하려는 문제
> **"뭘 먹고 싶은지 모르겠다. 그런데 먹고 싶은 게 없는 건 아니다."**

- 사람은 원하는 게 분명히 **있지만, 그걸 말로 꺼내지 못한다.**
- ChatGPT는 원하는 걸 **말로 설명해야** 추천해 준다. 바로 그걸 못 하는 사람이 우리 사용자다. → **ChatGPT와 다른 지점**

### ✅ 사용자 심리에서 알게 된 것

| 심리 | 뜻 | 기획에 반영한 것 |
|---|---|---|
| **회상 vs 재인** | 기억에서 직접 떠올리기(회상)는 어렵지만, 보기를 보고 알아보기(재인)는 쉽다 | "뭐 먹고 싶어?"라고 묻지 않고 **메뉴를 먼저 보여 준다** |
| **선택 과부하** | 선택지가 너무 많으면 오히려 고르지 못한다 | 한 번에 **5개 정도**만 보여 준다 |
| **조사에 대한 거부감** | "왜 물어봐? 어디에 쓰려고?" 하는 의심과 귀찮음 | **질문을 하지 않는다.** 개인정보(이름, 나이, 로그인)도 받지 않는다 |
| **대가 없는 질문** | 받은 것도 없는데 정보부터 달라고 하면 싫다 | **결과를 먼저 준다** |

### ✅ 핵심 아이디어
> **묻지 말고, 결과를 먼저 보여 주고, 클릭으로 마음을 읽어서, 점점 진짜 원하는 메뉴로 좁혀 간다.**

### ✅ 진행 흐름

```
[1라운드]  김치찌개  짜장면  초밥  햄버거  비빔밥      ← 처음엔 일반적인 추천
            ✓ 클릭            ✓ 클릭
                     [다음 ▶]
[2라운드]  김치찌개  된장찌개  짬뽕  비빔밥  순두부    ← 일부 메뉴는 빠지고, 끌린 쪽과 비슷한 메뉴가 채워짐
            ✓          ✓        ✓
                     [다음 ▶]
[3라운드]  ... 점점 "따뜻한 국물 + 한식" 쪽으로 좁혀짐
                     ▼
[최종]  여러 개의 "진짜 원하는 메뉴"
```

1. 앱을 열면 질문 없이 바로 메뉴 5개가 나온다. 처음엔 일반적인 추천이다.
2. 사용자는 끌리는 메뉴를 **클릭만** 한다.
3. **[다음]** 을 누르면 1~2개 메뉴가 빠지고 새 메뉴가 채워진다.
4. 반복할수록 그 사람의 **오늘 음식 성향**이 드러나고, 메뉴가 그쪽으로 좁혀진다.
5. 마지막에는 진짜 원하는 메뉴 여러 개를 보여 준다.

### ✅ 독립변수 (출발점)
처음 메뉴를 고를 정보가 하나도 없으면 1라운드가 무작위가 된다(**콜드 스타트 문제**). 그래서 기본 입력은 받기로 했다. 단, 조사받는 느낌이 들지 않도록 **버튼 클릭 위주로, 개인정보가 아닌 것만** 받는다.

| 구분 | 변수 | 방식 |
|---|---|---|
| 사용자 입력 | 식사 시간 | 아침 / 점심 / 저녁 / 야식 클릭. 현재 시각으로 미리 선택해 둠 |
| 사용자 입력 | 기분 | 😫피곤 · 😤스트레스 · 😢우울 · 😊좋음 · 😐보통 (선택) |
| 사용자 입력 | 인원수 | 혼자 · 2명 · 3~4명 · 5명 이상 (선택) |
| 사용자 입력 | 재료 | 글자 입력 (선택, 비워도 됨) |
| 자동 수집 | 계절, 요일 | 사용자 기기의 날짜로 계산 |
| ⏭ 나중 버전 | 날씨 | 위치 정보가 필요해서 지금은 하지 않기로 함 |

### ✅ "심리(음식 성향) 분석" 방법
- 모든 메뉴에 **특징표(태그)** 를 붙여 둔다.

  | 메뉴 | 국물 | 매운맛 | 종류 | 무게감 |
  |---|---|---|---|---|
  | 김치찌개 | O | 매움 | 한식 | 든든 |
  | 초밥 | X | 안 매움 | 일식 | 가벼움 |

- 클릭한 메뉴의 특징은 점수가 올라가고(+), 넘긴 메뉴의 특징은 점수가 내려간다(-).
- 쌓인 점수표가 곧 그 사람의 성향이고, 다음 메뉴는 점수가 높은 특징 위주로 고른다.

### ✅ 신뢰를 얻는 장치
- **개인정보를 받지 않는다.** 음식 반응만 본다.
- ~~추천 이유를 보여 준다~~ → **분석 결과는 보여 주지 않는다.** "당신은 ○○ 상태예요", 성향 태그, 추천 이유 같은 문구는 **분석당하는 느낌**을 준다. 분석은 뒤에서 메뉴를 고르는 데만 쓴다. (test 1.0을 써 보고 바꿈)
- **로컬 AI(Ollama)라서 정보가 밖으로 나가지 않는다.** ChatGPT 기반 앱은 이 말을 할 수 없다.
- 조사가 아니라 **놀이처럼** 느껴지게 만든다.

## 🛠 문제 해결 기록

> 증상 → 원인 → 해결 순서로 적습니다. 같은 문제가 또 생기면 여기부터 보세요.

### 1. 커밋이 안 됨 (`Author identity unknown`)
- **원인**: Git에 작성자 이름과 이메일이 설정돼 있지 않았음
- **해결**:
  ```
  git config --global user.name "이름"
  git config --global user.email "이메일"
  ```

### 2. PowerShell에서 `git` 명령을 찾을 수 없음
- **원인**: Git이 Windows PATH에 등록돼 있지 않아, Git Bash에서만 실행됨
- **해결**: Git Bash를 사용하거나, Git 설치 폴더의 `bin`을 시스템 환경변수 PATH에 추가

### 3. `python main.py`로 실행했더니 서버가 뜨지 않음
- **원인**: `main.py`는 서버 객체(`app`)를 정의만 하고, 직접 실행하는 코드는 없음
- **해결**: `uvicorn main:app --port 8000`으로 실행하거나 `docker compose up -d --build` 사용
- **참고**: `main.py`나 `docker compose up`을 실행해도 **LLM 모델은 자동으로 받아지지 않음**. 모델은 `ollama pull`로 직접 받아야 함

### 4. Git Bash의 curl로 한글 질문을 보내면 `400 There was an error parsing the body`
- **원인**: Windows Git Bash에서 curl 인자로 한글을 넘길 때 인코딩이 깨짐. 서버 문제가 아님
- **해결**: 브라우저(http://localhost:5500)에서 테스트하거나, 컨테이너 안에서 파이썬으로 요청을 보냄
  ```
  docker exec menu-backend python -c "import httpx; print(httpx.post('http://localhost:8000/api/chat', json={'messages':[{'role':'user','content':'점심 추천'}]}, timeout=300).json())"
  ```
