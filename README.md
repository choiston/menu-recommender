# 오늘 뭐 먹지? (menu-recommender) — `test 3.1`

<img src="frontend/title.png" alt="오늘 뭐 먹지 캐릭터" width="90" />

> **"뭘 먹고 싶은지 모르겠다. 그런데 먹고 싶은 게 없는 건 아니다."**
> 이런 사람을 위한 앱이에요. 묻지 않고 메뉴를 먼저 보여 줘요. 고른 메뉴를 따라 깊이 들어가며 후보를 찾고, **마지막 한 걸음은 AI가 대신 결정해 줘요.** 로그인하면 내 기록이 쌓여서 **내 취향에 맞춘 추천**과 **📒 내 기록**을 볼 수 있어요(선택 사항). 고민조차 귀찮다면 **🎰 나에게 맞춘 룰렛**도 있어요.

---

## 🍽️ 사용 방법 (test 3.1)

1. **시작 화면**: 식사 시간, 기분, 인원수, 필수 재료를 골라요.
   - 식사 시간은 현재 시각에 맞춰 미리 선택돼 있어요. 식사 시간을 뺀 나머지는 모두 선택 사항이에요.
   - **필수 재료**를 적으면 그 재료가 들어간 메뉴**만** 나와요.
   - 오른쪽 위 **🔑 로그인**은 선택이에요. 로그인하지 않으면 아무것도 저장하지 않아요.
   - **🎰 고민 말고 룰렛 돌리기!** (test 3.1): 위의 입력(+내 취향)에 맞춘 메뉴 10칸이 돌아가고 **🎉 오늘의 픽!** 이 나와요.
     - 카드: 칼로리 · 주재료 · 먹는 법 · **🗺️ 카카오맵에서 찾기**(근처 식당 검색) · ✅ 이걸로 먹을래요 · 🎲 다시 돌리기(바로 전 당첨은 안 나옴)
     - 우리 앱은 위치를 받지 않아요. 카카오맵이 사용자 위치로 근처 식당을 찾아 줘요.
2. **라운드 화면**: 끌리는 메뉴를 클릭하고 **[다음 ▶]** 을 눌러요. 고른 메뉴의 **관련 메뉴**가 이어서 나와요.
   ```
   국밥 ✓ → 돼지국밥 · 순대국밥 · 소머리국밥 · 콩나물국밥 · 뼈해장국
   ```
   - **🔀 다른 방향 보기**: **아직 안 가 본 종류**의 메뉴 5개가 **종류마다 1개씩** 나와요(10개 종류를 돌아가며).
   - **[◀ 이전]**: 앞 라운드로 돌아가요. **1라운드에는 없어요.** 시작 화면으로 가려면 오른쪽 위 **[↺ 처음으로]** 를 눌러요.
   - **[🤖 골라 줘!]**: 고르기를 끝내고, 고른 메뉴 중 하나를 골라 달라고 해요(예전 이름: 결과 보기).
3. **결과 화면**
   ```
   🤖 오늘은 이거예요!   🍲 뼈해장국 👑  💬 AI 코멘트 · 🔥 칼로리 · 🥩 주재료 · 💡 먹는 법  [✅ 이걸로 먹을래요]
   [🤔 One More Think!] → 🤔 이건 어때요? 콩나물국밥 ▼ (누르면 정보가 바로 밑에 펼쳐짐)
   📌 내가 고른 메뉴     감자탕 → 뼈해장국  + 고른 메뉴 카드 (여기서 직접 골라도 돼요)
   ```
   - **🤔 One More Think!**: 고른 메뉴 밖에서 하나씩 더 추천해요. 처음엔 가까운 메뉴, 점점 다른 종류로 가요. 결과는 **접힌 채로** 쌓이고, 누르면 정보가 펼쳐져요.
   - **📌 내가 고른 메뉴**: 화면 아래쪽에 **카드로** 보여요. AI 추천과 같은 메뉴는 위에 이미 있어서 빼요.
   - **🎰 고른 메뉴로 룰렛 돌리기** (test 3.1): 고른 메뉴가 2개 이상이면, 그 메뉴들로만 룰렛을 돌려 정할 수 있어요.
4. **[✅ 이걸로 먹을래요]** → **"맛있게 드세요! 🍽️"** 마무리 화면
   - 로그인했으면 **📒 내 기록에 저장**하고, 다음 추천부터 내 취향이 반영돼요.
   - 로그인하지 않았으면 저장하지 않아요. [🔑 로그인하고 이 기록 남기기]를 누르면 로그인한 뒤 그 결정을 저장해요.
5. **📒 내 기록** (로그인 사용자): 결정한 횟수, AI 추천을 그대로 고른 비율, 많이 고른 메뉴·종류·시간대, **🤖 AI가 본 내 취향**(기록 3개 이상), 결정 목록. 맨 아래에 **회원 탈퇴**(계정과 기록 모두 삭제)가 있어요.

## ▶️ 실행 방법

```
docker compose up -d --build
docker exec -it menu-ollama ollama pull llama3.1   # AI 코멘트용 모델 (처음 한 번만)
```

브라우저에서 **http://localhost:5500** 에 접속하면 돼요.

> - **DB(PostgreSQL)는 처음 켤 때 자동으로 준비돼요.** 표를 만들고, 비어 있으면 `backend/data/menus.json`의 메뉴 156개를 넣어요. 데이터는 `menu_db_data` 볼륨에 저장돼서 컨테이너를 다시 만들어도 남아요.
> - ⚠️ `docker compose down -v` 처럼 **`-v`를 붙이면 볼륨까지 지워져서 회원과 기록이 모두 사라져요.** 평소에는 `-v` 없이 쓰세요.
> - **AI(Ollama)는 문장 쓰기에만 써요**(결과 코멘트, 내 취향). 메뉴 고르기는 점수 계산으로 즉시 해요. AI가 꺼져 있어도 앱은 정해진 틀 문장으로 동작해요.
> - 더 작은 모델(llama3.2:3b)은 한국어 품질이 떨어져서 llama3.1(8B)을 써요. GPU가 없어서 코멘트는 10~30초 걸려요.

### API 주소

| 주소 | 로그인 | 하는 일 |
|---|---|---|
| `POST /api/round` | 선택 | 다음 라운드 메뉴 5개 (로그인하면 개인 취향 반영) |
| `POST /api/decide` | 선택 | 고른 메뉴 중 하나 → "오늘은 이거예요!" |
| `POST /api/onemore` | 선택 | One More Think!: 고른 메뉴 밖에서 하나 더 |
| `POST /api/roulette` | 선택 | **[test 3.1]** 🎰 룰렛 칸(나에게 맞춘 10개 또는 고른 메뉴) + 당첨 칸 번호 |

| `GET /api/me/records` | 필수 | 📒 내 기록: 결정 목록 + 통계 |
| `GET /api/me/insight` | 필수 | 🤖 AI가 본 내 취향 |

http://localhost:8001/docs 에 들어가면 API 문서를 보면서 직접 테스트해 볼 수 있어요.

### 컨테이너 구성

- `menu-ollama` : Ollama 서버 (포트 11434). 모델은 `ollama_data` 볼륨에 저장돼요.
- `menu-backend` : FastAPI 서버 (내 PC 포트 8001 → 컨테이너 8000).
- `menu-frontend` : 화면 파일 서버 (포트 5500)
- `menu-db` : **[test 3.0] PostgreSQL 16**. 내 PC로는 포트를 열지 않아서 backend만 접속할 수 있어요(더 안전, 다른 DB와 포트 충돌도 없음). 데이터는 `menu_db_data` 볼륨에 저장돼요.

## 📝 기획 노트 — 대화로 결정한 것

> 모든 것은 **대화로 먼저 정하고**, "실행"이라고 하면 그때 코드를 만들어요.
> ✅ 확정 · 🧪 임시로 정함(써 보고 다시 결정) · ⏳ 아직 안 정함 · ⏭ 나중 버전

### 1. 왜 이 앱을 만드나

| | 내용 |
|---|---|
| 처음 버전의 문제 | AI가 아이디어부터 코드까지 짠 채팅 앱이었어요. "점심 추천해줘"는 ChatGPT가 이미 더 잘해요. **똑같으면 만들 이유가 없어요.** |
| ✅ 해결하려는 문제 | **"원하는 건 있는데, 그게 뭔지 말로 꺼내지 못한다."** |
| ✅ ChatGPT와 다른 점 | ChatGPT는 원하는 걸 **말로 설명해야** 추천해 줘요. 바로 그걸 못 하는 사람이 우리 사용자예요. |

### 2. 사용자 심리 → 설계 원칙

| 심리 | 뜻 | ✅ 설계 원칙 |
|---|---|---|
| **회상 vs 재인** | 직접 떠올리기(회상)는 어렵지만, 보고 알아보기(재인)는 쉬워요 | 묻지 말고 **메뉴를 먼저 보여 준다** |
| **연상** | 하나를 보면 관련된 것이 떠올라요 ("국밥… 아, 순대국밥!") | **고른 메뉴를 따라 관련 메뉴로 깊이 들어간다** |
| **선택 과부하** | 선택지가 너무 많으면 고르지 못해요 | 한 번에 **5개**만 보여 준다 |
| **조사에 대한 거부감** | "왜 물어봐? 어디에 쓰려고?" | 개인정보(이름, 나이, 위치, 로그인)는 **받지 않는다** |
| **분석당하는 느낌** | "당신은 ○○ 상태예요"라는 말을 들으면 불편해요 | 분석을 **말로 보여 주지 않는다.** 대신 분석으로 **메뉴를 찾아 준다** |
| **대가 없는 질문** | 받은 것도 없는데 정보부터 달라면 싫어요 | **결과를 먼저 준다** |
| **마지막 결정의 어려움** | 후보를 손에 쥐고도 마지막에 하나를 못 골라요 | **마지막 한 걸음은 AI가 대신 결정**한다 ("오늘은 이거예요!") |

### 3. ✅ 핵심 아이디어
> **묻지 말고 → 먼저 보여 주고 → 고른 메뉴를 따라 깊이 들어가서 후보를 찾고 → 마지막 하나는 AI가 골라 준다.**
> 그래도 아니면 → **🤔 원 모어 띵크**로 AI가 다른 음식을 계속 찾아 준다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 라운드 | **사람** | 끌리는 메뉴를 클릭하며 실마리 찾기 (사람이 잘하는 일: 보고 알아보기) |
| 결과 | **AI** | 고른 후보 중 하나로 결정 + 다른 음식 제안 (사람이 힘들어하는 일: 마지막 결정) |

### 4. 결정 사항 정리

#### 시작 화면 (독립변수 = 출발점)
처음에 정보가 하나도 없으면 1라운드가 무작위가 돼요(**콜드 스타트 문제**). 그래서 기본 입력은 받기로 했어요. 대신 **버튼 클릭 위주로, 개인정보가 아닌 것만** 받아요.

| 항목 | 결정 | 상태 |
|---|---|---|
| 식사 시간 | 아침 / 점심 / 저녁 / 야식 **클릭**. 현재 시각으로 미리 선택해 둠 (5~10시 아침, 10~15시 점심, 15~21시 저녁, 나머지 야식) | ✅ |
| 기분 | 😫피곤 · 😤스트레스 · 😢우울 · 😊좋음 · 😐보통 (선택 사항) | ✅ |
| 인원수 | 혼자 · 2명 · 3~4명 · 5명 이상 (선택 사항) | ✅ |
| **필수 재료** | 글자로 입력 (선택 사항). 적으면 그 재료가 들어간 메뉴**만** 나옴(걸러내기). 메뉴가 적거나 없으면 안내. 여러 개 적으면 그중 하나라도 들어간 메뉴 (test 2.1: "당기는 재료"(가산점)에서 바꿈) | ✅ |
| 계절, 요일 | 사용자 기기의 날짜로 자동 계산 | ✅ |
| 날씨 | 위치 정보가 필요해서 지금은 하지 않음 | ⏭ |
| 안심 문구 | **"로그인하지 않으면 아무것도 저장하지 않아요. 로그인하면 내가 결정한 메뉴만 기록돼요."** (test 3.0에서 로그인이 생겨서 바꿈) | ✅ |

#### 라운드 화면
| 항목 | 결정 | 상태 |
|---|---|---|
| 클릭의 의미 | **"끌린다"** | ✅ |
| 다음 라운드 | 고른 메뉴의 **관련 메뉴**로 깊이 들어감 (test 1.0의 "비슷한 특징 찾기"에서 바꿈) | ✅ |
| 여러 개를 고르면 | 각 메뉴의 관련 메뉴를 **번갈아 섞어서** 보여 줌 | ✅ |
| 관련 메뉴 다음은 | 더 구체적으로 들어가기보다 **관련 메뉴로 넓히기** (몰랐던 메뉴를 발견하도록) | ✅ |
| 관련 메뉴가 모자라면 | "관련 메뉴의 관련 메뉴"(2단계 연결)로 채움 → 그래도 모자라면 지금까지의 성향 점수로 채움 | ✅ |

#### 종류 · DB · 로그인 · 개인 취향 (test 3.0에서 새로 정함)

### 5. 🔄 결정이 바뀐 과정 (왜 바꿨나)

| 언제 | 처음 생각 | 바뀐 결정 | 이유 |
|---|---|---|---|
| 기획 | 질문 없이 바로 메뉴 보여 주기 | 기본 질문(기분, 인원, 재료)은 받기 | 출발점(독립변수)이 있어야 1라운드가 의미 있음 |
| 기획 | 식사 시간은 자동 수집 | 사용자가 클릭으로 선택 (자동으로 미리 선택) | 점심시간에 저녁 메뉴를 고를 수도 있음 |
| test 1.0 후 | 결과에 "오늘 당신은 ○○ 상태예요" | 내가 고른 메뉴만 보여 주기 | 분석당하는 느낌 |
| test 1.0 후 | 비슷한 특징의 메뉴로 좁히기 | 고른 메뉴의 **관련 메뉴로 깊이 들어가기** | 고른 실마리를 직접 따라가야 "원하는지 몰랐던 것"을 찾을 수 있음 |
| test 1.0 후 | 최대 4라운드 | 제한 없음 | 깊이 들어가는 방식은 사람마다 필요한 단계가 다름 |
| test 2.0 | 먹는 팁을 인터넷 사이트에서 가져오기 | AI가 작성 (칼로리는 공공 데이터) | 블로그 글은 저작권 문제, 공공 데이터에는 먹는 팁이 없음 |
| test 2.0 후 | 결과 = 내가 고른 메뉴 목록 | **AI가 하나 골라 주기 + 원 모어 띵크** | 고른 걸 다시 보여 주기만 하면 앱이 한 일이 없음. 처음 계획("최종에는 진짜 원하는 메뉴")과 어긋남. "분석을 말로 보여 주기"는 피하되 "분석으로 메뉴를 찾아 주기"는 해야 함 |
| test 2.0 후 | 당기는 재료 (가산점) | **필수 재료 (걸러내기)** | "필수"라고 했는데 다른 메뉴가 나오면 "말을 안 듣네" 하고 신뢰를 잃음 |
| test 2.1 후 | 결과 화면의 "📌 내가 고른 메뉴: …" 한 줄 | 아래쪽에 **카드로** | 고른 메뉴도 정보를 보고 직접 고를 수 있어야 함 |
| test 2.1 후 | [이전]이 1라운드에서 시작 화면으로 감 | 1라운드에선 **숨김** + [↺ 처음으로] 따로 | 처음으로 가는 건 "처음" 버튼의 역할 |

| test 2.1 후 | 원 모어 띵크 | **One More Think!** | 영어 + 느낌표로 멋있게 |
| test 2.1 후 | One More Think! 카드가 다 펼쳐짐 | **접어 두고 누르면 펼침** | 추천이 쌓여도 화면이 길어지지 않게 |

## 🛠 문제 해결 기록

> 증상 → 원인 → 해결 순서로 적어요. 같은 문제가 또 생기면 여기부터 보세요.

### 1. 커밋이 안 됨 (`Author identity unknown`)
- **원인**: Git에 작성자 이름과 이메일이 설정돼 있지 않았음
- **해결**:
  ```
  git config --global user.name "이름"
  git config --global user.email "이메일"
  ```

### 2. PowerShell에서 `git` 명령을 찾을 수 없음
- **원인**: Git이 Windows PATH에 등록돼 있지 않아서 Git Bash에서만 실행됨
- **해결**: Git Bash를 사용하거나, Git 설치 폴더의 `bin`을 시스템 환경변수 PATH에 추가

### 3. `python main.py`로 실행했더니 서버가 뜨지 않음
- **원인**: `main.py`는 서버 객체(`app`)를 정의만 하고, 직접 실행하는 코드가 없음
- **해결**: `uvicorn main:app --port 8000`으로 실행하거나 `docker compose up -d --build` 사용
- **참고**: `main.py`나 `docker compose up`을 실행해도 **LLM 모델은 자동으로 받아지지 않음**. 모델은 `ollama pull`로 직접 받아야 함

### 4. Git Bash의 curl로 한글을 보내면 `400 There was an error parsing the body`
- **원인**: Windows Git Bash에서 curl 인자로 한글을 넘길 때 인코딩이 깨짐. 서버 문제가 아님
- **해결**: 브라우저나 http://localhost:8001/docs 에서 테스트하거나, 컨테이너 안에서 파이썬으로 요청을 보냄
  ```
  docker exec menu-backend python -c "import httpx; print(httpx.post('http://localhost:8000/api/round', json={'meal':'점심'}).json())"
  ```

### 5. 대화창에 붙여 넣은 그림을 앱에 쓰고 싶을 때
- **원인**: 대화창에 붙인 그림은 파일이 아니라서 바로 코드에서 쓸 수 없음
- **해결**: 그림을 PC에 파일로 저장한 뒤(이번에는 `Pictures/Screenshots/음식캘릭터.png`) `frontend/title.png`로 복사함
- **주의**: 인터넷에서 가져온 그림이면 **사용 허락(저작권)** 을 확인해야 해요. 워터마크가 있는 그림은 보통 허락 없이 공개 서비스에 쓰면 안 돼요.

### 6. 서버를 켠 직후 첫 AI 코멘트가 항상 틀 문장으로 나옴
- **원인**: CPU로 AI를 돌리면 모델(4.9GB)을 메모리에 처음 올리는 데 40초 이상 걸려서 시간 초과(40초)가 남
- **해결**: 서버가 켜질 때 짧은 요청을 미리 보내 모델을 올려 두고(워밍업), `keep_alive: 30m`로 30분 동안 메모리에 남겨 둠
- **참고**: 서버를 켜고 1분쯤 지나면 코멘트가 10~15초 안에 AI 문장으로 나와요. 응답의 `source`가 `template`이면 틀 문장, `ai`면 AI가 쓴 문장이에요.

### 7. 백엔드가 DB보다 먼저 켜져서 연결 실패할 수 있음 (test 3.0에서 미리 대비)
- **원인**: `depends_on`은 "시작 순서"만 보장하고, DB가 접속을 받을 준비가 됐는지까지는 기다리지 않아요.
- **해결**: `db.wait_for_db()`가 2초마다 다시 접속을 시도해요(최대 60초). 여러 서비스를 함께 돌릴 때의 기본 패턴이에요.

### 8. 회원과 기록이 갑자기 다 사라짐
- **원인**: `docker compose down -v`처럼 `-v`를 붙이면 DB 볼륨(`menu_db_data`)까지 지워져요.
- **해결**: 평소에는 `docker compose down`(볼륨 유지)만 쓰세요. 메뉴는 다시 켤 때 `menus.json`에서 자동으로 채워지지만, **회원과 기록은 되돌릴 수 없어요.**

### 9. 셸 명령의 따옴표가 꼬여서 명령 전체가 실행되지 않음 (test 3.1 작업 중)
- **원인**: 긴 명령 안에 작은따옴표, 큰따옴표, HTML이 섞이면 셸(bash)이 따옴표 짝을 잘못 읽어요.
- **해결**: 긴 내용은 **파일로 먼저 저장**하고, 짧은 스크립트(파이썬)로 바꿔 넣었어요. 바꿀 문자열을 못 찾으면 바로 멈추게(`assert`) 해서 엉뚱한 곳이 바뀌지 않게 했어요.
